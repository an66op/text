## 验证方法

`npm run check:all` 检查两套前端与 Go；`npm run verify:stack` 对运行服务执行真实 HTTP 验证；Go 使用 `TEST_DATABASE_URL` 对两个独立连接池做持久化、并发转账与回滚测试。

HTTP 验证包含：注册/会话、401/403与来源、跨账号社区互动、频道发布与会话隔离、个人备份revision冲突、测试积分请求幂等和余额守恒、后台审核/举报/审计、退出撤销。验证会保留带 `qa_` 标记的本地示例，最近报告位于 Git 忽略的 `.runtime/verify-result.json`。

项目工具链升到 Go 1.27.3，依赖锁定；对可导入代码执行 govulncheck。后续依赖或工具链变动需重跑，不把一次扫描当作永久安全结论。

本轮实际结果：前台 44 个测试文件、290 项通过；后台 3 个文件、16 项通过；两端类型、Lint、生产构建与格式检查通过。Go race / vet 和配置真实 PostgreSQL 的并发集成通过。HTTP 八组流程通过。govulncheck 未发现可达或导入包漏洞，所需模块另有一项未被调用的通告。项目路径含空格及单引号时，独立临时 PostgreSQL 的创建、启动、连接和停止已实测通过，测试目录已清理。

## 当前不能声称完成的部分

- 当前 Work 设置禁止本地浏览器控制，浏览器 inventory 返回空并明确报 disabled。本轮未做截图、真实浏览器或真机布局验收；组件交互测试与静态构建不代替视觉验收。
- 当前机器没有 Docker。容器文件与生产部署说明需要在具备 Docker/HTTPS 的环境中实际构建、启动、验证；本地已验证的是原生开发进程。
- PostgreSQL 使用单行 JSONB 与事务行锁。所有写事务串行化，需要规范化表、索引及分域事务后再进行容量验证。
- 在线消息为 HTTP 轮询，尚无 WebSocket、投递确认、服务端未读；原主社交列表仍为本机数据。
- 头像和帖子媒体接收公开图片链接，尚无对象存储/上传服务；本机演示媒体不是服务器媒体库。
- 浏览器钱包连接仅读公开地址/链；测试 GEM 与外部钱包分别管理，没有 SIWE、合约、真实资金或收益服务。
- 圈子、匹配、商城、影音、阅读和 AI 仍有本机演示能力。前台入口及 README 明确区分，后续按 NEXT_PHASE 逐项迁移。
