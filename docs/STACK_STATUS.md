# 本地全栈交付记录

日期：2026-10-27。当前已完成第二轮基础链路优化，仍有媒体、圈子、商城、AI 等服务需要迁移；不代表已完成最终量产或高流量上线。

## 实际运行与数据升级

前台 5173、React 运营后台 5174、Go API 8080、项目私有 PostgreSQL 16 / 55432 均已运行。

本地运行库已从 schema v1 单行状态迁移至 v2 权威关系表：账号/会话、帖子/点赞/评论、通讯/成员/消息/已读、个人文档、举报/审计、钱包/分录/幂等、outbox/事件序列。旧表更名 `gongming_legacy_state_v1` 留存，运行时不依赖它。迁移前完成 pg_dump 与隔离恢复；停旧 API 后启动新版本完成事务迁移。

迁移核验：旧账号、帖子、消息、会话 ID 缺失数均为0；凭据、原消息正文与发送者、旧钱包余额差异均为0。迁移前建立的真实 Cookie 在新服务上仍可验证同一账号，无需重新登录。新版本备份再次恢复到独立临时数据库成功，19张业务表可读，演练数据库已清理。

普通 handler 仍以全域一致快照执行业务，再按实体增量写关系表；这是当前明确的读放大边界，需要继续按域 SQL、容量验证与服务拆分。所有普通写入没有全站 JSONB 行锁；SERIALIZABLE 冲突重跑整个事务回调。实时分发有专用 SQL，只读流/会话/成员相关表。

## 当前产品行为

- 登录后的主社交使用真实账号消息；成员目录可搜索、查看资料、发起私聊和举报。个人页与桌面头像同步账号资料，本机资料不被登录覆盖。
- 本机社交与通讯录保留 `/social/demo`、`/contacts/demo`；访客可体验本机内容，服务不可达时显式提示，不能以演示替代服务器结果。
- 消息有每会话 seq、clientId 去重、稳定历史游标、未读与可见消息已读水位。失败/刷新后的待发需手动重试并复用 ID，草稿按账号和会话隔离。
- 手机端消息顶部、连接状态和输入区悬浮于滚动内容上；输入框外透明，框内保留玻璃效果。动态测量实际高度，已读判断排除被遮挡区域，加载历史保留阅读位置。
- WebSocket 使用事务 outbox、最小失效通知、跨实例读事件、重放、过期resync、心跳和注销关闭；断线时显示状态并保留轮询。API 与 WS 都验证预期账号，防同域多标签页 Cookie 换账号串写。
- 个人备份、世界、运营审核与测试积分沿用实际 PostgreSQL 数据；测试积分没有现金价值，公开钱包连接不替代签名认证。

## 本轮验证

两端类型、Lint、生产构建通过；前台50个测试文件316项、后台3个文件16项通过；数据库工具3项目标边界测试通过。Go race/vet、配置真实PG的规范化迁移/回滚/约束/并发/跨实例WS测试通过。新依赖与工具链继续执行govulncheck，不把一次扫描当永久保证。

`npm run verify:stack` 的8组真实HTTP流程通过。`npm run verify:messages` 经运行中5173 Vite代理完成6组真实WebSocket验证：握手/Cookie、实时收消息/去重、未读/已读、seq历史/断线重放、非成员/Origin/账号隔离、注销断连。两者都会保留本地QA示例，便于在前后台查看，不能对生产运行。

专门修复并覆盖的账号边界：A请求晚到401不能退出B；旧账号私密响应不能落入新账号；世界发布草稿切账号清空；陈旧标签页不能退出另一Cookie账号；网络验证失败保留已知身份，避免突然回本机演示。备份工具清理libpq重定向环境变量，并将自动恢复目标固定到验证过的loopback。
