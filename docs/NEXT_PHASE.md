# 共鸣：全栈后的实施顺序

目标继续是以社交为中心的综合产品。保留五个一级入口与透明导航，避免新能力不断堆叠主导航。当前 Go / PostgreSQL、React 前后台的第一条业务链路已落地；「后端暂不开发」的旧阶段约束已被新的全栈目标替代。

## 已接通的第一条链路

账号登录 → 服务器世界发帖 → 跨账号评论/点赞 → 举报 → 后台审核 → 公开列表下架 → 站内通知与审计追溯。登录后主社交已接私聊/群组/广播频道、未读水位、游标历史、消息去重与WebSocket；通讯录包含真实好友申请、关系与基础群管理。圈子已接创建、审批、角色、邀请、讨论/公告、图文审核与治理，图片按圈授权；作者失权后仍可删除本人圈帖清理引用。v0.7.0的14类通知与业务原子提交，按账号查询、失权动态脱敏，read-all保护新到通知；图片审核可定位本人上传记录。通讯录和我统一真实身份，设备撤销与个人备份可用；Web3仍为测试积分与公开钱包连接。消息、图片读取及通知使用按域SQL，圈子等普通域仍需消除全域快照成本。其余原型独立演示，不替代服务器出错状态。

## 接下来的交付顺序

| 优先级 | 范围             | 验收标准                                                                                                                                                                                   |
| ------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1      | 规范化数据库     | schema7权威关系表、约束、迁移和恢复演练已落地；消息、图片读取与通知已使用按域SQL，继续迁移圈子、会话管理、设备与其它域，并完成真实容量压测                                                 |
| 2      | 社交通讯统一     | 主入口、幂等键、未读/已读、游标历史、WebSocket/outbox、好友关系/申请和基础群管理已接通；继续完善公告/邀请审批/分级管理员/解散归档、搜索索引、引用/撤回、附件、投递状态与旧记录显式导入     |
| 3      | 媒体与身份完善   | JPEG/PNG上传、私有存储、引用权限、前后台审核、本人清理及一致性恢复已交付；继续对象存储/签名上传、缩略图、自动孤儿核对、视频转码；邮箱验证/找回密码、服务端隐私/黑名单仍待接通              |
| 4      | 圈子成为社区核心 | 创建/审批、角色、邀请、频道/图文、治理、站内通知与本人引用清理已交付；继续活动报名、资料与真实圈聊，沿用当前成员/频道权限。通知后续做实时订阅/外部推送、保留策略与容量验证，不重复聊天未读 |
| 5      | 商业与内容服务   | 商品库存与订单状态机、阅读进度与书架服务、影音目录、匹配双向同意；支付仅在专门服务具备签名回调、退款和对账后开放                                                                           |
| 6      | AI 服务          | Go 代理模型服务，密钥仅服务端，配额、停止与重试、隐私范围和流式错误；本地演示始终明确；工具操作需要实际授权                                                                                |
| 7      | Web3 身份        | SIWE 挑战 nonce、域/URI/有效期/链/签名校验、一次性消费与重放防护；钱包绑定/解绑与账号恢复；当前公开地址连接不能替代认证                                                                    |
| 8      | Web3 社区实验    | 独立测试网、审计合约、非托管交易确认、链上事件与重组处理；使用凭证或社区积分做产品实验，真实资产或收益产品另行设计和审核                                                                   |
| 9      | 高流量运行       | 分布式限流、缓存、队列、事件分析与推荐、监控告警、压测容量、恢复演练；运营行为审计与数据保留策略                                                                                           |

当前测试账本已有原子双边记账、幂等、不可变分录与数据库平衡约束；真实资产仍需独立总账审计、外部对账、风险控制与资产隔离，不能把测试积分服务直接用于支付或链上资产。

## 每一阶段的完成条件

- 前台与后台入口、刷新、返回、权限失效、加载、空态、错误重试都可用；手机软键盘、安全区和长内容不遮挡操作。
- `npm run check:all`、格式检查、真实数据库集成和 HTTP 联调通过；新增检查覆盖实际风险，不只是复述实现。
- 展示至少一个跨账号成功示例和一个失败恢复示例；状态来自实际持久化服务。
- 旧本机数据迁移必须先预览、确认和可恢复；不得在登录时静默覆盖本机内容。
- 浏览器与真机验收有实际证据；工具禁用时记录尚未验证，不能把构建通过称为视觉通过。
- 文档明确哪些已经真实联通、哪些仍演示、哪些尚未接外部服务。

参考标准：[EIP-6963 多钱包发现](https://eips.ethereum.org/EIPS/eip-6963)、[EIP-4361 SIWE](https://eips.ethereum.org/EIPS/eip-4361)。
