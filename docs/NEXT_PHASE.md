# 下一阶段：从完整页面前端到接口可接入产品

产品继续以社交为主，保留「社交、通讯录、发现、AI、我」五个一级页面。社交按私聊、群组、Telegram 式广播频道组织；发现包含动态、世界、直播、视频、圈子、匹配、短视频、小说、游戏、商城；我只有钱包、设置，书架位于小说页。二级页面不显示底部主菜单。

## 本轮交付基线

本轮把好友申请、联系人资料、群管理、聊天搜索、消息详情、通话演示、发布、短视频评论、阅读设置、个人设置和钱包操作收敛到独立路由。聊天保留单行输入及下方加号面板；动态采用封面与圆头像资料区，手机帖子列表贴合页面边缘。2026-10-15 的视觉更新统一了 iOS 风格的导航、分组和控件，详见 [设计说明](DESIGN_SYSTEM.md)。所有能力仍使用本地测试数据，后端暂不开发。

验收以实际用户流程为准：页面入口、下一步、完成状态、返回、直接访问与刷新均需可用。类型检查和构建通过只是工程基线，不能代替这些验收。

## 实施顺序

| 批次             | 范围                   | 具体交付与验收                                                                                                                    |
| ---------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1 · 前端体验     | 手机可用性与辅助功能   | 真机软键盘、iOS 安全区、长内容、超长昵称、慢网图片；键盘焦点、表单报错和减少动画偏好；360–430px 手机与桌面均不遮挡主要操作        |
| 2 · 社交可靠性   | 可恢复的消息与会话状态 | 为本地模拟提供发送中、失败重试、断线恢复、分页历史；消息 ID、引用、撤回、草稿及未读规则形成明确契约，刷新后状态一致               |
| 3 · 数据边界     | 前端 Mock / API 可切换 | 定义用户、联系人、好友申请、群、消息、动态、评论与媒体的请求/响应类型；统一错误和分页字段；页面只调用领域服务，测试保持可独立运行 |
| 4 · 内容可靠性   | 影音和阅读             | 媒体加载失败与重试、视频暂停/切换/进度恢复、短视频预加载与资源释放、小说分章加载；在慢网和断网演示下仍能返回与恢复                |

第一到第四批继续只做前端。第五批先形成可审阅的接口和数据设计，实际后端开发按后续任务安排。

## 首条接口闭环

顺序为登录会话 → 我的资料 → 联系人 → 会话列表 → 历史消息 → 发消息 → 实时回执。需要明确重发的幂等键、历史分页游标、未读计算、附件上传结果和错误恢复。动态、评论、直播、组织等模块复用用户与媒体身份，避免每个模块自建一套身份系统。

钱包始终展示本地模拟标识。当前资产、报价、收款地址、兑换、转账及理财申购赎回均不产生链上或支付行为。理财使用固定演示年化，可用余额和持仓本金保存于同一钱包状态。后续是否接入真实资产服务，需要独立产品和服务端设计。匹配同样使用本机演示资料，后续真实服务需要单独设计身份、隐私和双向同意流程。

商城订单与 AI 回复均为前端演示。后续商城服务需单独定义商品、库存、订单与支付边界；AI 接口需要由服务端代理并明确会话数据范围，不能在浏览器保存服务密钥。频道浏览数是本机演示计数，真实订阅、互动和计数需要服务端身份与幂等控制。

## 每批交付要求

- `npm run check` 与 `npm run format:check` 通过。
- 关键路由能够直接打开、刷新、前进和返回，二级页面无底栏。
- 完整演示至少一条正常流程，以及无结果、无效 ID、提交失败与恢复流程。
- 保留已有本地数据；版本变更采用迁移，损坏记录有回退。
- 提供手机视图的实际预览证据；记录尚需后端或真机验证的能力。
