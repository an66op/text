# 共鸣 · 社交平台

手机优先的社交产品，前台与运营后台均为 React 19 / Vite / TypeScript，服务端为 Go，数据库为 PostgreSQL。主导航保留「社交、通讯录、发现、AI、我」；顶部透明、标题居中，二级页面独立路由且不显示主底栏。

当前已经接通账号、主社交实时消息、好友申请与关系、群组/频道管理、成员目录、服务器世界、运营审核、个人备份和测试积分账本。登录后的「社交、通讯录、我」使用同一个真实账号；影音、小说、圈子、匹配、商城及 AI 仍保留完整的本机演示流程。下面区分各模块的实际能力，避免把演示当作已上线服务。

## 一次启动四个服务

需要 Node.js 22+、npm、Go（项目自动选择 1.27.3+ 工具链）、PostgreSQL 16+。`initdb`、`pg_ctl`、`psql`、`createdb` 需在 PATH 中。本地不依赖 Docker。

```sh
npm ci
npm run dev:all
```

首次会创建项目私有数据库、自动迁移并初始化开发示例，再启动 API、前台与后台。数据库只监听本机，数据保存在 Git 忽略的 `.runtime/postgres`，不会使用或重置系统的 5432 实例。

| 服务       | 地址                                                                |
| ---------- | ------------------------------------------------------------------- |
| 产品前台   | [localhost:5173](http://localhost:5173)                             |
| 运营后台   | [localhost:5174](http://localhost:5174)                             |
| Go API     | [127.0.0.1:8080/api/v1/health](http://127.0.0.1:8080/api/v1/health) |
| PostgreSQL | `127.0.0.1:55432/gongming`                                          |

Ctrl+C 停止三项应用进程；数据库保留运行。`npm run db:down` 停止数据库，`npm run db:up` 再次启动，不删除数据。已有进程占用端口时启动器会明确退出，避免启动到另一端口后看错版本。

| 开发账号               | 密码         | 用途                       |
| ---------------------- | ------------ | -------------------------- |
| `demo@gongming.local`  | `Demo2026!`  | 成员、发帖、会话、测试积分 |
| `admin@gongming.local` | `Admin2026!` | 运营、内容审核、举报、审计 |

这些账号仅在 `APP_ENV=development` 初始化。生产模式拒绝开发种子数据库，需要独立数据库和管理员配置。同一主机名的前台与后台共用会话 cookie；同时体验两个账号时请使用不同浏览器或隐身窗口。`localhost` 与 `127.0.0.1` 的 cookie 独立。

## 五分钟看懂这套产品

1. 从「我」资料卡下进入账号，填入成员示例登录；进入「发现 → 世界」，发布一条想法，点赞或评论。
2. 直接进入「社交」。示例包含私聊、群组、广播频道；也能从目录选择成员创建会话。频道订阅者只能阅读，频道主可以发布。消息带服务器未读与已读水位，断线后重连补齐；失败消息需手动重试，同一请求不会重发多份。点通讯录里的成员资料可发起私聊。
3. 在另一浏览器打开运营后台，用管理员登录。在「内容审核」搜索刚发布的文字，确认下架。刷新公开世界后该内容消失；操作审计中有记录。举报中心可查看示例工单并填写处理说明。
4. 进入「我 → 钱包 → Web3 实验室」，领取 1,000 测试 GEM，向 `gongming`（共鸣团队）转送少量积分。刷新可保留结果；服务端按请求编号处理重试。测试 GEM 没有现金价值。
5. 进入「账号 → 个人备份」，勾选阅读进度、书架或草稿，预览后确认备份。另一设备登录同账号后可选择恢复；版本冲突会阻止旧数据覆盖新备份。
6. 如果浏览器装有兼容的钱包扩展，Web3 页可选择钱包并读取公开地址与网络。当前只连接公开身份，尚未开放签名登录、链上交易、充值或提现。
7. 进入「账号 → 登录设备」，查看当前账号的真实登录会话。可撤销单项或其它全部会话；撤销当前会话后重新验证登录状态。旧登录没有完整设备记录时会如实显示「未记录」。

### 体验好友和群组的完整流程

在普通窗口登录成员示例，另一浏览器或隐身窗口登录管理员示例并打开产品前台。两个窗口不要共用同一个主机名的 Cookie。

1. 成员端进入「通讯录 → 发现」，搜索 `gongming`，打开共鸣团队资料，点「添加好友」并填写一句说明。
2. 团队端进入「通讯录 → 申请 → 收到」，接受后，两端「好友」都出现对方。发出的申请可撤销，收到的申请可拒绝；移除好友保留原私聊。
3. 进入社交里的群组，点聊天右上角进入「聊天信息」。当前群主可改名、添加和移除成员，或在成员右侧转交管理身份；普通成员可退出。
4. 频道使用同一套管理入口。转交后旧频道主成为普通成员，新频道主可以发布；全站运营管理员不会因角色自动获得频道发言或管理权。添加成员会开放此会话原有历史，操作前在页面有说明。

升级后好友初始为空是正常现象：已有私聊、目录成员和频道订阅都不会自动变成好友。

## 能力与数据边界

| 范围                                   | 当前行为                                                        | 持久化                                 |
| -------------------------------------- | --------------------------------------------------------------- | -------------------------------------- |
| 账号 `/login`、`/register`、`/account` | 注册、登录、过期与退出、个人资料                                | Go / PostgreSQL，HttpOnly 会话         |
| 登录设备 `/settings/devices`           | 本人会话列表、单项/其它会话撤销、当前设备退出                   | 服务器会话，撤销同步关闭实时连接       |
| 世界 `/world`                          | 搜索、话题、分页、图片链接、发帖、点赞、评论、举报、删除        | 服务器共享数据                         |
| 社交 `/social`、兼容 `/messages`       | 私聊、群组、频道、游标历史、未读、失败重试、WebSocket与成员管理 | 服务器成员权限、事务 outbox 与消息     |
| 运营后台 5174                          | 总览、用户角色与封禁、内容审核、举报处理、操作审计、系统状态    | 服务端角色授权、事务审计               |
| 个人备份 `/account/sync`               | 手动选择、预览、上传、恢复、版本冲突保护                        | 按账号隔离的个人文档                   |
| Web3 `/web3`                           | 测试 GEM 补给、原子转送、幂等重试、公开钱包连接                 | 服务器测试账本；地址连接不作为登录认证 |
| 通讯录 `/contacts`、成员 `/u/:handle`  | 好友、申请、发现、成员资料、公开动态、发起私聊与举报            | 服务器双向关系和成员目录，不暴露邮箱   |
| 本机 `/social/demo`、`/contacts/demo`  | 旧好友申请、群管理、消息管理和通话界面                          | 独立本机演示，不随登录自动上传         |
| 动态、圈子、匹配、影音、小说、游戏     | 完整页面、路由、示例内容与本机交互                              | 浏览器本地；直播与语音房为演示         |
| 钱包 `/wallet`、理财 `/wallet/earn`    | 固定演示报价、模拟申购、赎回、转账、收款二维码                  | 本机模拟，与服务器 GEM 分离            |
| 商城 `/shop`                           | 商品、购物车、模拟结算与订单                                    | 本机模拟，不支付或配送                 |
| AI `/ai`                               | 本地示例回复、流式显示、停止、重试、草稿与历史                  | 本机演示，未接模型服务                 |

真实动态详情为 `/world/p/:postId`，旧数字动态链接继续可用。未登录时保留可操作的社交演示，登录后切换到真实消息；服务暂时离线时会显示错误，不自动伪装成本机数据。旧世界内容保留在 `/world/demo`，可以从世界页「本机内容」进入。原动态草稿发布到本机世界后会跳回该页面。书架仍位于小说内部；个人页没有动态、收藏、喜欢及数量统计；圈子与匹配在发现短视频之前。共享帖子、会话、订单或资产不通过个人备份接口上传，避免信任客户端授权数据。

远程 Unsplash / Pravatar 示例图片需要网络；视频使用公开 CC0 演示素材。没有短信、邮件验证、密码找回、媒体上传存储、真实支付、生产 AI 或链上资产服务。设置中的隐私、黑名单和安全码仍用于本机演示；真实账号权限与会话由服务器校验。

## 检查与运行命令

| 命令                                       | 用途                                                 |
| ------------------------------------------ | ---------------------------------------------------- |
| `npm run dev:all`                          | 数据库、API、前台、后台统一启动                      |
| `npm run dev` / `dev:admin` / `dev:server` | 单独启动前台 / 后台 / Go                             |
| `npm run db:up` / `db:down` / `db:status`  | 管理隔离数据库                                       |
| `npm run check:all`                        | 前台类型/Lint/测试/构建、后台构建/测试、Go race 测试 |
| `npm run verify:stack`                     | 对运行中的 API 做真实 HTTP 与数据库联调              |
| `npm run build` / `build:admin`            | 构建前台 `dist/` 与后台 `admin/dist/`                |
| `npm run format:check`                     | 全工程格式检查（Go 由 gofmt 管理）                   |

`npm run verify:messages` 进一步通过运行中的 5173 Vite 代理验证真实 WebSocket、未读、断线重放、去重、成员隔离，以及多设备会话隐私、单项/其它/当前会话撤销。`npm run test:tooling` 覆盖数据库工具的目标边界。

`npm run verify:social` 通过 5173 代理验证三账号好友申请/接受/拒绝/取消/移除、私聊保留、群管理权限、移除后访问拒绝、转交与频道发布权。该脚本只允许本机 5173/5174/8080，结果写入 Git 忽略的 `.runtime/verify-social-result.json`，不会记录口令或 Cookie。

验证脚本会创建带 `qa_`、`ws` 或 `social_` 前缀的本地测试账号，并保留会话、好友申请、举报与已下架测试帖，便于后台查看；不要对生产环境运行。注册接口有速率限制，连续频繁执行会返回 429。

真实数据库并发测试使用临时 schema，结束后自动清理，不修改应用表：

```sh
cd server
TEST_DATABASE_URL='postgres://gongming:gongming_dev@127.0.0.1:55432/gongming?sslmode=disable' go test -race ./...
go vet ./...
```

没有配置测试数据库时，Go 数据库集成测试会明确跳过；普通单元测试通过不代表已验证数据库。测试范围和最近验证结果见 [运行与验收记录](docs/STACK_STATUS.md)。

```text
src/                      产品前台，feature 划分、懒加载路由与公共 API 层
  features/platform/      账号、共享世界、在线通讯
  features/web3/          测试账本、浏览器钱包连接
  features/sync/          显式个人备份与恢复
  features/...            社交、圈子、内容、AI、商城等现有业务
admin/                    独立 React / Vite / TS 运营后台
server/                   Go API、PostgreSQL 持久化、权限与事务、测试
scripts/                  数据库管理、应用启动、HTTP 联调
 deploy/                  生产容器与反向代理配置（需部署环境验证）
docs/                     接口契约、设计说明、阶段记录
```

前后端接口详见 [API 契约](docs/API_CONTRACT.md)，服务配置与权限规则见 [Go API 说明](server/README.md)，界面约束见 [设计系统](docs/DESIGN_SYSTEM.md)，圈子演示见 [圈子说明](docs/CIRCLES.md)。

当前服务端主数据已迁移到规范化关系表，有唯一约束、外键、索引、不可变审计与账本保护。事务采用一致快照读取、SERIALIZABLE 增量写入和冲突重试。消息列表、详情、历史、发送和已读五个端点已使用按域 SQL，WebSocket 使用独立 outbox SQL；其它业务仍有全域快照读取。消息访问路径、实测开销和剩余边界见 [查询路径说明](server/QUERY_PATHS.md)；继续压测与服务拆分后才能承诺大流量能力。后续实施与验收见 [下一阶段规划](docs/NEXT_PHASE.md)。

前后台请求均有覆盖响应体读取的20秒期限。写入超时可能已提交，页面提示先刷新确认，不自动重发；账号切换后丢弃旧私密响应，旧页面卸载后不能继续发账号操作。运营后台可见时定期重新验证会话，网络短暂失败保留已知身份并提示重试。

## 数据库升级与恢复演练

从旧版本升级前先停掉应用写入、执行 `npm run db:backup` 并保存路径。新 API 自动事务迁移到 schema v4，保留旧 ID、会话、内容、审计和账本；v2 权威关系表及 v3 好友申请/双向好友表为运行数据。旧单行表更名为 `gongming_legacy_state_v1` 留存，运行时不再依赖。v3 不从旧私聊推断好友，也不改写原 v2 数据。v4 为会话追加独立公开随机 ID、粗粒度设备和可空历史时间，不改旧凭据或虚构登录时间；详情见 [会话迁移说明](server/migrations/004_sessions.md)。不要让旧版 API 与新版同时写同一数据库。回退应在停服后从升级前备份恢复到独立数据库验证，再切换连接，不能直接把旧 API 指向迁移后的数据库。

```sh
npm run db:backup
npm run db:restore-check -- /备份文件的绝对路径.dump
```

自动恢复演练只允许本机项目 55432 实例，创建全新临时数据库，验证恢复后删除该临时库；不会覆盖运行库。工具清理 libpq 的环境重定向变量，备份与报告位于 Git 忽略且仅当前用户可访问的 `.runtime/backups`。生产备份、保留、加密及异地恢复仍需独立运行方案。
